# Likan Expo app

Native Expo SDK 57 app with Expo Router and on-device Storybook.

## Project layout

```text
src/
  app/                 Expo Router routes and layouts
  components/
    ui/                Reusable Expo UI wrappers and shared prop types
    visuals/           Shared visual components
  features/
    auth/              Native authentication screens and form adapters
    onboarding/        Three native introduction pages shown on first launch
    launch/            Launch-screen experience
    maps/              Map screens and platform implementations
    skia/              Skia experience and platform loading
    storybook/         Development and preview Storybook screen integration
  hooks/               Shared hooks and platform implementations
  context/             Auth restoration and native TanStack Query providers
  guards/              Auth predicates for protected route groups
  lib/                 Shared QueryClient and pure entity cache keys
  services/            Typed entity services, TanStack hooks and auth/session services
  constants/           Shared colors and layout values
  types/               API DTOs and shared declarations
  shared/locales/      French, English and Arabic app translations
  validation/
    schemas/           Zod validation schemas and inferred form types
    resolvers/         React Hook Form resolver adapters
.rnstorybook/
  components/          Storybook-only helpers and canvases
  stories/
    components/        Reusable component stories
    forms/             Login form, field group and OTP stories
  main.ts              Story discovery and addons
  preview.tsx          Shared preview configuration
  index.tsx            On-device Storybook entry
  storybook.requires.ts Generated by Storybook; do not edit
assets/                Fonts, images, and animations
docs/                  Selector reference and project notes
.maestro/              Shared native Android/iOS UI test flows
tests/components/      Component behavior and Storybook checks
tests/forms/           Form validation and interaction checks
```

Import app source with `@/`, assets with `@assets/`, and the Storybook entry with `@storybook`. Reusable UI components must not import Storybook helpers or stories. Keep non-route code outside `src/app/`. Platform-specific implementations stay next to their shared component.

Retain existing dependencies for planned features, even when they are not yet used. Remove a dependency only when explicitly requested.

## Development

App labels use the dictionaries adapted from `reference/shared/locales`. Select
Français, English or العربية in the page footer or profile sheet. The saved choice
restores on startup; Arabic uses RTL without reloading the app. See
[localization](docs/localization.md) for conventions and verification.

The first launch shows one introduction screen with Discover, Cook, and Save
slides before sign-in. The wordmark, progress and actions stay fixed while bundled
food photography and text swipe horizontally in a native carousel. Next and
Previous move through the same content; swipe direction follows the selected
language. Each slide can scroll vertically for enlarged text. Skip or Let’s get started saves
`onboardingCompleted` in AsyncStorage. Later launches and sign-outs keep that
preference. Startup waits for the preference before choosing a route, and a failed
save offers a retry without marking the introduction complete.
Storybook is limited to **Components** and **Forms**, with focused stories.
Use Controls to explore themes, disabled states and other prop variations.

- `npm start` starts Metro.
- If another project already uses port 8081, run `npm start -- --port 8082` and
  open this app with `i` or `a` from that Metro terminal. Reopen the development
  link after changing ports so the installed app connects to this project's server.
- Use Node 22.18 or newer and `npm ci` to install the locked dependencies.
- `npm run check` runs TypeScript, lint, formatting, and component/form tests.
- `npm test` runs both suites; `npm run test:components` or `npm run test:forms` runs one.
- `npm run lint` checks app source, Storybook source, and project scripts/configuration with zero warnings allowed.
- `npm run typecheck` checks app source, platform implementations, and Storybook stories with strict TypeScript.
- `npm run test:e2e` runs native component/form flows on a connected development build.
- `npm run format` applies the shared formatting rules; `npm run format:check` checks them.
- `npm run storybook:generate` regenerates story discovery after adding or moving stories.
- `npm run storybook` starts a development-client Metro session with a fresh cache for native Storybook.

`npm ci` also installs the Husky pre-commit hook. Each commit runs ESLint fixes
followed by Prettier on staged JavaScript/TypeScript files, and Prettier on staged
JSON, Markdown, YAML, CSS and HTML files. Lint errors or warnings block the commit;
the full `npm run check` remains the CI gate. Run `npm run lint:staged` to check
staged changes manually. Hook installation is skipped in CI, production installs,
or when `HUSKY=0` is set.

Install the workspace's recommended ESLint and Prettier VS Code extensions to
enable lint fixes and formatting on save. Prettier is pinned to an exact version
so dependency updates do not unexpectedly change formatting.

See [local SonarQube analysis](docs/sonarqube.md) for the dashboard, scan scope,
credentials, and repeat-scan commands.

Open **Browse all pages** and select **Storybook** in a development or preview build to browse native stories. Signed-out testers can use **Browse all pages as guest (dev)** on Login. See [guest browsing and preview builds](docs/development-guest-mode.md) and [the test-ID reference](docs/storybook-test-ids.md) for selectors and SDK limitations.

Native Storybook and its on-device addons use `10.7.0` with Storybook core
`10.6.2`. Install with `npm ci`: `package-lock.json` and npm overrides keep the
renderer versions aligned and share the app's SDK-compatible native modules.
The obsolete Yarn lockfile was removed because Yarn Classic ignores those
overrides and could install a second `react-native-safe-area-context`, crashing
Storybook with duplicate `RNCSafeAreaProvider` registration. After updating
dependencies, restart Metro with `npm run storybook`.

Direct links such as
`myappexpo://storybook?STORYBOOK_STORY_ID=components-button--interaction&mode=canvas`
open the requested fixture even on the first lazy load. Canvas mode hides the
Storybook panels and disables selection persistence; normal entry keeps them.

Run `npm run test:e2e` with Maestro installed and a development build connected to Metro. See [native UI testing](docs/native-ui-tests.md) for device setup, individual flows, and platform requirements.

Signed-out users start at **Login**, with registration, email verification, and password recovery in one native auth stack. The **Account** tab shows the signed-in identity and logout. Set `EXPO_PUBLIC_API_URL` in `.env.local` and restart Metro after changing it. See [auth forms](docs/auth-forms.md) for the backend contract and test IDs. See [tests](tests/README.md) for the focused component/form suite.
