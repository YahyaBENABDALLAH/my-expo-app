## Review observations

- Search filters and sample recipe sheets calculate their scroll height from the whole window. Their formulas do not explicitly subtract sheet padding, safe-area insets or keyboard height.
- Sample card width uses window width with a 48-point padding assumption. Card image height uses a ratio of that explicit width. Native parent measurements are already used for input, sheet and stepper bridges.
- The tab bar contains repeated 56/84 dimensions and the floating action repeats 76. Its central slot uses start: 50% and marginStart: -42. The 84-point slot with 4-point padding corresponds to the 76-point action; this relationship is encoded as literals.
- Text height is generally intrinsic, with a default lineHeight derived from font size. Explicit viewports, image ratios and decorative canvases account for most custom height handling.
- These are static source observations. Native layout, keyboard interaction and text clipping were not evaluated in this audit.
